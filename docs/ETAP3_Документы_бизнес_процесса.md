# Этап 3: Документы бизнес-процесса

Описание документов: «Заказ», «ЗаказКодовМаркировки», обработка/документ «Результат работы станции» — структура реквизитов, связи с регистром и очередью обмена (очередь детализируется на Этапе 4). Реквизит «Ответственный» в документах имеет тип **СправочникСсылка.Сотрудники** (справочник «Сотрудники» создаётся отдельно).

---

## 1. Документ «Заказ»

Формируется менеджером: клиент (контрагент), номенклатура, объём, тип продукции (ЛС/БАД). Основа для заказа кодов маркировки и для привязки результатов нанесения/агрегации со станции.

### 1.1. Реквизиты шапки

| Реквизит | Тип | Назначение |
|----------|-----|------------|
| Дата | Дата | Дата заказа |
| Номер | Строка | Номер (при автонумерации — по правилам конфигурации) |
| Контрагент | СправочникСсылка.Контрагенты | Клиент заказа |
| Ответственный | СправочникСсылка.Сотрудники | Ответственный (менеджер); при использовании ролей — пользователь с ролью «МенеджерМаркировки» |
| Комментарий | Строка, необязательно | Произвольный комментарий |

Страна маркировки определяется реквизитом **Контрагент.Страна** (справочник Контрагенты).

### 1.2. Табличная часть «Товары»

| Реквизит | Тип | Назначение |
|----------|-----|------------|
| Номенклатура | СправочникСсылка.Номенклатура | Позиция номенклатуры (с заполненным GTIN и типом продукции в справочнике) |
| Количество | Число | Количество к выпуску/маркировке |

**Примечание:** тип продукции (ЛС/БАД) не хранится в документе — подставляется на форме из справочника **Номенклатура.ТипПродукции**. Страна маркировки не хранится в строке — берётся из справочника **Контрагенты.Страна** (контрагент заказа).

При необходимости в табличную часть добавляют реквизиты для комментария по строке, единицы измерения и т.д.

### 1.3. Поведение

- Документ не проводится в регистры учёта (или проводится только в регистр для отчётов/аналитики — по решению). Основа бизнес-логики — создание документа «ЗаказКодовМаркировки» по заказу и привязка к нему поступлений кодов и результатов станции.
- При удалении/пометке на удаление заказа учитывать наличие связанных документов «ЗаказКодовМаркировки» и «ПоступлениеКодовМаркировки» (контроль или предупреждение — на усмотрение).

---

## 2. Перечисление «СтатусВыполненияЗаказаКодов»

Статус выполнения заказа кодов маркировки (для отображения в формах документа «ЗаказКодовМаркировки» без обязательного чтения очереди обмена).

| Имя значения | Синоним |
|--------------|---------|
| Черновик | Черновик |
| КВыполнению | К выполнению |
| Отправлен | Отправлен |
| Выполнен | Выполнен |
| Ошибка | Ошибка |

Используется в реквизите **СтатусВыполнения** документа «ЗаказКодовМаркировки».

---

## 3. Документ «ЗаказКодовМаркировки»

Оформляется оператором кодов по заказу: привязка к заказу и его строкам, объём запрашиваемых кодов (с запасом). Инициирует запрос к API (через очередь обмена на Этапе 4) и связывает полученные коды с заказом через документ «ПоступлениеКодовМаркировки» и регистр «КодыМаркировки».

### 3.1. Реквизиты шапки

| Реквизит | Тип | Назначение |
|----------|-----|------------|
| Дата | Дата | Дата заказа кодов |
| Номер | Строка | Номер документа |
| Заказ | ДокументСсылка.Заказ | Заказ, по которому запрашиваются коды |
| Ответственный | СправочникСсылка.Сотрудники | Ответственный (оператор кодов) |
| СтатусВыполнения | ПеречислениеСсылка.СтатусВыполненияЗаказаКодов | Статус выполнения заказа кодов (Черновик, К выполнению, Отправлен, Выполнен, Ошибка) |

**Оператор маркировки** в документе не хранится. Он определяется при формировании запроса к API: страна берётся из **Заказ.Контрагент.Страна** (справочник Контрагенты), активный оператор — из справочника **ОператорыМаркировки** (запись с данной Страной и **Активный** = Истина).

### 3.2. Табличная часть «Коды»

Повторяет строки заказа с объёмом запроса кодов (как правило, количество с запасом).

| Реквизит | Тип | Назначение |
|----------|-----|------------|
| Номенклатура | СправочникСсылка.Номенклатура | Номенклатура (из заказа) |
| КоличествоЗаказа | Число | Количество по заказу (для справки) |
| КоличествоКодов | Число | Запрашиваемое количество кодов (≥ КоличествоЗаказа, с запасом) |

**Примечание:** тип продукции (ЛС/БАД) не хранится в табличной части — подставляется на форме из справочника **Номенклатура.ТипПродукции**. Номер строки заказа при записи в регистр **КодыМаркировки** берётся из стандартного номера строки табличной части (он совпадает с номером строки заказа при заполнении из документа «Заказ»).

При необходимости добавляют реквизит «Страна» по строке, если один заказ кодов объединяет несколько стран.

### 3.3. Логика при записи/проведении

- **При записи (или по кнопке «Заполнить»):** заполнение табличной части из документа **Заказ**: строки «Товары» → строки «Коды» с копированием Номенклатура, Количество (как КоличествоЗаказа); **КоличествоКодов** по умолчанию = Количество по заказу (пользователь может увеличить для запаса). Тип продукции на форме подставляется из Номенклатура.ТипПродукции.
- **При проведении (или по отдельной кнопке «Поставить в очередь»):** вызов общей логики постановки в очередь обмена (Этап 4): тип операции «Заказ кодов», данные документа/строк (заказ, номенклатура, GTIN, тип продукции, объём кодов). Оператор для запроса определяется по **Заказ.Контрагент.Страна** и активной записи справочника **ОператорыМаркировки**. Очередь затем обрабатывается регламентным заданием или вручную; при успешном ответе API создаётся документ **ПоступлениеКодовМаркировки** с заполнением **ОтветAPIБинарный**, при проведении которого формируются записи регистра **КодыМаркировки** с привязкой к заказу, номеру строки (стандартный номер строки табличной части), номенклатуре, оператору (тому же, что определён по стране заказа), документу поступления.

Связь «ЗаказКодовМаркировки» → «ПоступлениеКодовМаркировки» может быть по реквизиту в шапке ПоступлениеКодов (документ-результат) или по поиску документа поступления по ЗаказКодов (один заказ кодов — один или несколько документов поступления — в зависимости от API).

## 4. Обработка или документ «Результат работы станции»

Оператор на производстве выгружает из станции маркировки/агрегации файл с результатом (JSON) и загружает его в 1С с привязкой к заказу и позициям. На основе загруженных данных формируются данные для отчётов в API (нанесение/агрегация) и постановка в очередь отправки (Этап 4).

### 4.1. Вариант: внешняя обработка «Загрузка результата станции»

- **Входные данные:** файл JSON от станции; выбор заказа (документ **Заказ**) и при необходимости отбор строк.
- **Действия:** разбор JSON; сопоставление данных из файла с позициями заказа (по номенклатуре, кодам, партии и т.д. — по формату станции); формирование набора данных для отчётов о нанесении и/или агрегации; постановка в очередь обмена (типы операций «Отчёт нанесения», «Отчёт агрегации»); обновление статусов кодов в регистре **КодыМаркировки** (например, «Использован») для задействованных кодов.
- **Форма:** выбор файла, выбор заказа, таблица сопоставления «строка заказа — данные из файла», кнопка «Загрузить и поставить в очередь».

### 4.2. Вариант: документ «РезультатРаботыСтанции»

- **Шапка:** Дата, Заказ (ДокументСсылка.Заказ), ФайлJSON (ХранилищеЗначения или путь к загруженному файлу).
- **Табличная часть:** НомерСтрокиЗаказа, Номенклатура, Количество нанесённых/агрегированных, данные для отчёта (коды, идентификаторы — по структуре API). При проведении — постановка в очередь отправки отчётов и обновление статусов в регистре **КодыМаркировки**.

Выбор варианта (обработка или документ) — по удобству учёта и отчётности; логика разбора JSON и формирования сообщений для API общая (Этап 4–5).

### 4.3. Формат JSON станции

Структура файла от станции задаётся техническим заданием на станцию. В общем случае в JSON присутствуют: идентификаторы кодов маркировки (DataMatrix), при агрегации — связь «упаковка — вложенные коды», номенклатура или GTIN, количество. При реализации разбора (Этап 4–5) опереться на реальный формат станции и документацию API оператора (нанесение/агрегация).

---

## 5. Связи между документами

```
Заказ (документ)
    │
    ├── ЗаказКодовМаркировки (один или несколько на заказ)
    │       │
    │       └── ПоступлениеКодовМаркировки (создаётся при получении ответа API)
    │               └── движения в регистр КодыМаркировки
    │
    └── Результат работы станции (загрузка JSON, привязка к заказу/строкам)
            └── очередь обмена: отчёты нанесения/агрегации в API
```

- **Заказ** — исходный документ для заказа кодов и для привязки результатов станции.
- **ЗаказКодовМаркировки** — инициирует запрос кодов в API (через очередь); результат прихода кодов — документ **ПоступлениеКодовМаркировки** и записи в **КодыМаркировки**.
- **Результат работы станции** — загрузка JSON станции, привязка к заказу, постановка в очередь отправки отчётов (нанесение/агрегация) и обновление статусов кодов.

---

## 6. Порядок создания (Этап 3)

1. Создать перечисление **СтатусВыполненияЗаказаКодов** (Черновик, КВыполнению, Отправлен, Выполнен, Ошибка).
2. Создать документ **Заказ** с реквизитами шапки и табличной частью **Товары** (п. 1.1–1.2). Реализовать форму списка и форму документа.
3. Создать документ **ЗаказКодовМаркировки** с реквизитами шапки и табличной частью **Коды** (п. 3.1–3.2). Реализовать заполнение из заказа и кнопку/логику постановки в очередь (заглушка до реализации очереди на Этапе 4).
4. Реализовать проведение документа **ПоступлениеКодовМаркировки**: при проведении формировать записи регистра **КодыМаркировки** (номенклатура, заказ, номер строки — стандартный номер строки ТЧ, оператор, документ поступления, статус «ВНаличии»). Разбор бинарного ответа API и извлечение кодов — при реализации обмена по оператору (Этап 4–5).
5. Создать внешнюю обработку **ЗагрузкаРезультатаСтанции** или документ **РезультатРаботыСтанции** (п. 3.1–3.2): загрузка JSON, привязка к заказу, постановка в очередь отчётов (заглушка до Этапа 4) и при необходимости обновление статусов кодов в регистре.

После выполнения Этапа 3 переходят к Этапу 4 (очередь обмена, логирование, HTTP-клиент, обработка очереди).
