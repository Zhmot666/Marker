# Этап 1: Фундамент и настройки — перечень метаданных

Документ описывает объекты конфигурации, которые нужно создать в EDT (или в конфигураторе) для реализации Этапа 1.

---

## 1. Функциональные опции (включение/отключение по странам)

Создать четыре функциональные опции. Хранилище значения — константа (см. ниже).

| Имя (синоним) | Имя для кода | Назначение |
|---------------|--------------|------------|
| ИспользоватьМаркировкуКазахстан | ИспользоватьМаркировкуКазахстан | Включение функционала маркировки для Казахстана |
| ИспользоватьМаркировкуУзбекистан | ИспользоватьМаркировкуУзбекистан | Включение функционала маркировки для Узбекистана |
| ИспользоватьМаркировкуРоссия | ИспользоватьМаркировкуРоссия | Включение функционала маркировки для России |
| ИспользоватьМаркировкуБеларусь | ИспользоватьМаркировкуБеларусь | Включение функционала маркировки для Беларуси |

Для каждой функциональной опции: тип — «Логический», способ хранения — константа с тем же именем (см. константы ниже).

## 2. Константы (настройки подключения и поведения)

### 2.1. Включение стран (для функциональных опций)

| Имя | Тип | Назначение |
|-----|-----|------------|
| ИспользоватьМаркировкуКазахстан | Булево | Включена ли маркировка КЗ |
| ИспользоватьМаркировкуУзбекистан | Булево | Включена ли маркировка УЗ |
| ИспользоватьМаркировкуРоссия | Булево | Включена ли маркировка РФ |
| ИспользоватьМаркировкуБеларусь | Булево | Включена ли маркировка РБ |

### 2.2. Настройки обмена (общие)

| Имя | Тип | Назначение |
|-----|-----|------------|
| МаркировкаОтключитьМодальныеВопросыПередОтправкой | Булево | Отключить модальные вопросы «Продолжить/Отменить» перед отправкой запроса на сервер (для тестирования) |

Константа **МаркировкаТаймаутЗапросаСекунды** используется, когда у активного оператора в справочнике «ОператорыМаркировки» реквизит **Таймаут** не заполнен (резервное значение по умолчанию, например 30 секунд).

### 2.3. Справочник «ОператорыМаркировки» (настройки по оператору)

Один справочник для всех стран. Для каждой страны создают минимум две записи: рабочий и тестовый сервер (различаются значением **ОкружениеОператораМаркировки**). В каждый момент для одной страны активна только одна запись (см. реквизит **Активный**).

| Реквизит | Тип | Назначение |
|----------|-----|------------|
| Страна | ПеречислениеСсылка.Страны | Страна оператора (Казахстан, Узбекистан, Россия, Беларусь) |
| РабочийURL | Строка | URL сервера API (для выбранного окружения — рабочего или тестового) |
| ОкружениеОператораМаркировки | ПеречислениеСсылка.ОкружениеОператораМаркировки | Рабочий или Тестовый сервер |
| Активный | Булево | Признак активного сервера для данной страны. Для одной страны может быть активен только один оператор |
| КлючAPI | Строка | Ключ/токен API (при необходимости) |
| Таймаут | Число, необязательно | Таймаут HTTP-запроса в секундах (например, 30). Если не заполнен, используется константа МаркировкаТаймаутЗапросаСекунды или 30 |

**Поведение при записи (обязательно реализовать):** при установке реквизита **Активный** = **Истина** у одной записи справочника для всех остальных записей с тем же значением **Страна** реквизит **Активный** должен быть установлен в **Ложь**. Реализуется в обработчике **ПередЗаписью** или **ПриЗаписи** справочника «ОператорыМаркировки» (при записи элемента: если записываемый элемент.Активный = Истина, выполнить обновление других элементов с той же Страной, установив у них Активный = Ложь).

**Примечание:** при записи элемента справочника с **Активный** = Истина в обработчике **ПередЗаписью** для остальных элементов с той же **Страной** устанавливается **Активный** = Ложь (реализовано в модуле справочника).

## 6. Общий модуль «НастройкиОбменаМаркировкиСервер»

- **Сервер** — да (вызывается на сервере).
- **Клиент (управляемое приложение)** — нет (или да, если понадобится читать настройки на клиенте для отображения).

В модуле разместить:
- чтение константы отключения модальных вопросов;
- получение настроек по стране из справочника «ОператорыМаркировки» (активный оператор): URL, окружение, ключ API, таймаут;
- функцию проверки «нужно ли показывать модальный вопрос перед отправкой» и получения текста вопроса (сервер, окружение);
- функции получения текущего URL, окружения, ключа API и таймаута по стране (через данные активного оператора).

Текст процедур/функций — в файле `ОбщийМодуль_НастройкиОбменаМаркировки.bsl` в этой папке (модуль в конфигурации: **НастройкиОбменаМаркировкиСервер**).

---

## Порядок создания в EDT

1. Создать перечисления «Страны» и «ОкружениеОператораМаркировки».
2. Создать константы (п. 2).
3. Создать функциональные опции (п. 1), указав способ хранения — соответствующие константы.
4. Создать роли (п. 3).
5. Создать общий модуль «НастройкиОбменаМаркировкиСервер» и перенести в него код из `ОбщийМодуль_НастройкиОбменаМаркировки.bsl`.

После этого можно подключать логику модального вопроса в обработчике отправки запросов (при реализации очереди обмена).

---

## Вызов модального вопроса перед отправкой

Перед выполнением запроса к API (из обработки очереди или из формы):

1. Определить **страну** и **окружение** (тест/прод): например, `Окружение = НастройкиОбменаМаркировкиСервер.ПолучитьОкружениеОператора(Страна)`.
2. Если `НастройкиОбменаМаркировкиСервер.НуженМодальныйВопросПередОтправкой()` = **Истина** — показать диалог:
   - Текст: `НастройкиОбменаМаркировкиСервер.ПолучитьТекстПодтвержденияОтправки(Страна, Окружение)`.
   - Кнопки: «Продолжить» / «Отменить» (реализация через `ПоказатьВопрос(..., РежимДиалогаВопрос.ДаНет)` или аналог; при «Нет» — прервать отправку).
3. Если пользователь выбрал «Отменить» — не выполнять HTTP-запрос и выйти из процедуры.
4. Если модальные вопросы отключены или пользователь нажал «Продолжить» — выполнить отправку.
