# Этап 4: Очередь обмена, логирование и HTTP-клиент

Описание подсистемы интеграции с API: регистр очереди обмена, регистр логов, перечисления, общие модули для HTTP-запросов и работы с JSON. Без БСП.

---

## 1. Перечисление «ТипОперацииОчередиМаркировки»

Тип операции при обращении к API оператора маркировки.

| Имя значения | Синоним |
|--------------|---------|
| ЗаказКодов | Заказ кодов |
| ОтчетНанесения | Отчёт нанесения |
| ОтчетАгрегации | Отчёт агрегации |
| ПроверкаСтатуса | Проверка статуса |
| ПолучениеСправочников | Получение справочников |

При необходимости добавляют другие типы по мере подключения операторов.

---

## 2. Перечисление «СтатусЗаписиОчередиМаркировки»

Статус записи в очереди обмена.

| Имя значения | Синоним |
|--------------|---------|
| КВыполнению | К выполнению |
| Выполнен | Выполнен |
| Ошибка | Ошибка |
| ТребуетРазбора | Требует ручного разбора |

## 3. Регистр сведений «ОчередьОбменаМаркировки»

Очередь сообщений для отправки в API. Обрабатывается регламентным заданием или вручную (обработка/кнопка).

**Режим записи:** независимый (без регистратора).

**Измерения:**

| Измерение | Тип | Назначение |
|-----------|-----|------------|
| Идентификатор | УникальныйИдентификатор | Уникальный идентификатор записи (новый UUID при создании). Используется как первичный ключ |

**Ресурсы:**

| Поле | Тип | Назначение |
|------|-----|------------|
| ТипОперации | ПеречислениеСсылка.ТипОперацииОчередиМаркировки | Тип операции (заказ кодов, отчёт нанесения и т.д.) |
| ТелоЗапроса | Строка или ХранилищеЗначения | Тело HTTP-запроса (JSON). При большом объёме — ХранилищеЗначения |
| ДокументЗаказКодов | ДокументСсылка.ЗаказКодовМаркировки, необязательно | Ссылка на документ заказа кодов (для операций, связанных с заказом кодов) |
| Статус | ПеречислениеСсылка.СтатусЗаписиОчередиМаркировки | К выполнению / Выполнен / Ошибка / Требует разбора |
| СчетчикПовторов | Число | Количество выполненных попыток отправки |
| ДатаСледующейПопытки | Дата | Дата и время следующей попытки (при ошибке и повторе) |
| ТекстОшибки | Строка, необязательно | Текст ошибки при неуспешной отправке |
| ДатаСоздания | Дата | Дата и время создания записи |

**Периодичность:** непериодический. Одна запись — одно сообщение в очередь.

**Обработка очереди:** регламентное задание или ручной запуск (обработка) выбирает записи со Статус = КВыполнению и ДатаСледующейПопытки ≤ ТекущаяДата(), выполняет HTTP-запрос, обновляет Статус и при ошибке — СчетчикПовторов, ДатаСледующейПопытки, ТекстОшибки. При достижении лимита повторов — Статус = ТребуетРазбора. Страна и URL определяются по ДокументЗаказКодов (через Заказ.Контрагент.Страна) или из тела запроса.

## 4. Регистр сведений «ЛогОбращенийAPIМаркировки»

Лог всех обращений к API: запрос, ответ, результат. Тело ответа хранится в бинарном виде (коды маркировки могут содержать непечатные символы).

**Режим записи:** независимый (без регистратора).

**Периодичность:** непериодический. Одна запись — одно обращение к API.

**Измерения:**

| Измерение | Тип | Назначение |
|-----------|-----|------------|
| Идентификатор | УникальныйИдентификатор | Уникальный идентификатор записи (новый UUID при создании). Первичный ключ |

**Ресурсы:**

| Ресурс | Тип | Назначение |
|--------|-----|------------|
| МоментВремени | Дата | Дата и время обращения |
| ТипОперации | ПеречислениеСсылка.ТипОперацииОчередиМаркировки | Тип операции |
| Страна | ПеречислениеСсылка.Страны | Страна оператора |
| Узел | Строка, необязательно | Имя узла кластера (при клиент-серверном варианте) |
| Успешно | Булево | Истина — успешный ответ, Ложь — ошибка |
| КодОтветаHTTP | Число, необязательно | HTTP-код ответа (200, 404, 500 и т.д.) |
| ТелоЗапроса | Строка или ХранилищеЗначения, необязательно | Тело отправленного запроса (для разбора инцидентов) |
| ТелоОтветаБинарный | ХранилищеЗначения | Тело ответа API в бинарном виде (основное хранение) |
| ТекстОшибки | Строка, необязательно | Текст ошибки при неуспехе |
| ИдентификаторЗаписиОчереди | УникальныйИдентификатор, необязательно | Идентификатор записи очереди (если вызов из очереди) |

**Примечание:** при большом объёме логов можно перейти на периодический режим по дню: добавить измерение Период (Дата, начало дня) и оставить Идентификатор для уникальности в пределах дня. Это упростит очистку старых записей.

**Запись в лог:** при каждом HTTP-обращении к API (из обработки очереди или при прямой отправке) — создание записи лога с полным телом запроса и ответа (бинарный ответ в ТелоОтветаБинарный).

## 5. Общий модуль «HTTPКлиентМаркировки» (серверный)

Функции для выполнения HTTP-запросов к API маркировки.

- **ВыполнитьЗапрос(URL, Метод, ТелоЗапроса, Заголовки, ТаймаутСекунды)** — выполняет HTTP-запрос (GET/POST и т.д.), возвращает структуру: Успешно, КодОтветаHTTP, ТелоОтветаБинарный, ТекстОшибки.
- Использовать **HTTPСоединение** или **HTTPЗапрос** (встроенные объекты 1С). Тело ответа читать как двоичные данные (ДвоичныеДанные), сохранять в ХранилищеЗначения без перекодирования.

---

## 6. Общий модуль «JSONМаркировки» (серверный)

Функции для работы с JSON (сериализация, десериализация, разбор).

- **ПрочитатьJSON(ДвоичныеДанныеИлиСтрока, Кодировка)** — чтение JSON из двоичных данных или строки, возврат структуры/массива/значения.
- **ЗаписатьJSON(Значение)** — сериализация в JSON-строку (для тела запроса).
- При необходимости — функции разбора ответа «заказ кодов» (извлечение кодов из JSON) по формату конкретного оператора (детализация на Этапе 5).

---

## 7. Общий модуль «ОчередьОбменаМаркировки» (серверный)

Логика работы с очередью и вызова API. Образец кода: [ОбщийМодуль_ОчередьОбменаМаркировки.bsl](ОбщийМодуль_ОчередьОбменаМаркировки.bsl).

- **ДобавитьВОчередь(ТипОперации, ТелоЗапроса, ДокументЗаказКодов)** — создание записи в регистре «ОчередьОбменаМаркировки» со Статус = КВыполнению. Страна определяется по ДокументЗаказКодов.Заказ.Контрагент.Страна.
- **ОбработатьОчередь()** — выбор записей к выполнению, для каждой: определение страны по ДокументЗаказКодов; проверка модального вопроса (если вызов инициирован пользователем с клиента — вопрос показывается на клиенте до вызова; при регламентном задании модальный вопрос не показывается), получение URL и параметров из НастройкиОбменаМаркировкиСервер, вызов HTTPКлиентМаркировки.ВыполнитьЗапрос, запись в лог, обновление статуса записи очереди и при успехе — создание/проведение документа ПоступлениеКодовМаркировки (для типа «Заказ кодов») или постановка следующих операций.
- **ПовторнаяПопытка(ЗаписьОчереди, ИнтервалМинут)** — установка ДатаСледующейПопытки = ТекущаяДата() + ИнтервалМинут, увеличение СчетчикПовторов.

**Модальный вопрос:** при ручном запуске обработки очереди (кнопка в форме) — перед отправкой запроса на сервер вызывать проверку НастройкиОбменаМаркировкиСервер.НуженМодальныйВопросПередОтправкой() и при Истина — показать на клиенте диалог с текстом НастройкиОбменаМаркировкиСервер.ПолучитьТекстПодтвержденияОтправки(Страна, Окружение). При «Отменить» — не выполнять запрос. При регламентном задании модальный вопрос не показывается (или константа ОтключитьМодальныеВопросы = Истина).

---

## 8. Обработка ошибок и повторы

- **Максимум повторов:** константа **МаркировкаМаксимумПовторовОчереди** (по умолчанию 5 при пустом значении).
- **Интервал между повторами:** константа **МаркировкаИнтервалПовтораОчередиМинут** (по умолчанию 5 при пустом значении).
- **Статус «Требует разбора»:** при СчетчикПовторов ≥ максимума или при определённых кодах ошибки (например, 4xx — не повторять автоматически).
- **Ручной разбор:** обработка **ОчередьОбменаМаркировки** — форма со списком записей очереди, кнопки «Обработать» и «Повторить» для выбранной записи.

---

## 9. Регламентное задание

- **Имя:** «Обработка очереди обмена маркировки».
- **Метод:** ОчередьОбменаМаркировки.ОбработатьОчередь().
- **Расписание:** по необходимости (например, каждые 5–10 минут или по крону).
- **Использование:** Истина (включено).

---

## 10. Порядок создания (Этап 4)

1. Создать перечисление **ТипОперацииОчередиМаркировки** (ЗаказКодов, ОтчетНанесения, ОтчетАгрегации, ПроверкаСтатуса, ПолучениеСправочников).
2. Создать перечисление **СтатусЗаписиОчередиМаркировки** (КВыполнению, Выполнен, Ошибка, ТребуетРазбора).
3. Создать регистр сведений **ОчередьОбменаМаркировки** (непериодический) с полями по п. 3.
4. Создать регистр сведений **ЛогОбращенийAPIМаркировки** (периодический по дню или непериодический) с полями по п. 4.
5. Создать общий модуль **HTTPКлиентМаркировки** (серверный) с функцией ВыполнитьЗапрос.
6. Создать общий модуль **JSONМаркировки** (серверный) с функциями чтения/записи JSON.
7. Создать общий модуль **ОчередьОбменаМаркировки** (серверный) с процедурами ДобавитьВОчередь и ОбработатьОчередь.
8. Реализовать в документе **ЗаказКодовМаркировки** (при проведении или по кнопке) вызов ОчередьОбменаМаркировки.ДобавитьВОчередь с формированием тела запроса по формату API (детализация на Этапе 5 для Казахстана/Узбекистана).
9. Создать регламентное задание «Обработка очереди обмена маркировки».
10. При необходимости — создать обработку для ручного запуска очереди и просмотра записей со статусом «Ошибка» / «Требует разбора».

## 11. Объекты к созданию вручную (спецификации)

Ниже — только описания. Объекты создаются в конфигураторе/EDT вручную.

### 11.1. Константа «МаркировкаМаксимумПовторовОчереди»

- **Тип:** Число (10, 0), неотрицательное.
- **Синоним:** «Максимум повторов очереди обмена маркировки».
- **Назначение:** максимальное число повторов при ошибке отправки; при достижении — статус «Требует разбора».
- **Использование в коде:** в `ОчередьОбменаМаркировкиСервер.ОбработатьОчередь()` вместо захардкоженной 5: читать константу, при пустом или ≤ 0 подставлять 5.

### 11.2. Константа «МаркировкаИнтервалПовтораОчередиМинут»

- **Тип:** Число (10, 0), неотрицательное.
- **Синоним:** «Интервал между повторами очереди обмена, минут».
- **Назначение:** интервал в минутах до следующей попытки при ошибке.
- **Использование в коде:** в `ОбработатьОчередь()` и в `ПовторнаяПопытка(ИдентификаторЗаписи, ИнтервалМинут)` — при не переданном/пустом интервале брать значение константы, иначе подставлять 5.

### 11.3. Обработка «ОчередьОбменаМаркировки»

- **Тип:** Обработка (DataProcessor).
- **Синоним:** «Очередь обмена маркировки».
- **Форма по умолчанию:** форма «Форма».

**Форма «Форма»:**

- **Реквизит формы:** `СписокОчереди` — тип DynamicList.
  - **Основная таблица:** `InformationRegister.ОчередьОбменаМаркировки`.
  - **Поля списка:** Идентификатор, ТипОперации, ДокументЗаказКодов, Статус, ТекстОшибки, ДатаСоздания.
- **Элемент:** таблица с путём к данным `СписокОчереди`, колонки по этим полям.
- **Кнопка «Обработать»** (на командной панели формы): команда формы `Обработать`.
- **Кнопка «Повторить»** (на командной панели таблицы): команда формы `Повторить`, привязка к текущей строке.

**Команды формы и обработчики:**

- **Обработать:** на сервере вызвать `ОчередьОбменаМаркировкиСервер.ОбработатьОчередь()`, затем обновить список (`СписокОчереди.Обновить()`).
- **Повторить:** на клиенте взять `Элементы.СписокОчереди.ТекущиеДанные`, проверить, что строка выбрана и заполнен `Идентификатор`; вызвать серверную процедуру, передав `ИдентификаторЗаписи`; на сервере — `ОчередьОбменаМаркировкиСервер.ПовторнаяПопытка(ИдентификаторЗаписи)` (интервал при необходимости из константы), затем `СписокОчереди.Обновить()`.

**После создания:** добавить обработку в состав конфигурации (в Configuration.mdo — `dataProcessors`). Константы — в `constants`.
